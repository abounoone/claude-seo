# 1C-Bitrix: Пошаговый чеклист онбординга

*Для нового разработчика на существующем интернет-магазине*
*Обновлено: 2026-03-21*

## Фаза 1 — Первый день: Доступы и инвентаризация

### 1.1 Получить и проверить доступы

- [ ] SSH-ключ добавлен на сервер (`~/.ssh/authorized_keys`)
- [ ] FTP/SFTP работает (только если нет SSH)
- [ ] Доступ к `/bitrix/admin/` — проверить логин администратора
- [ ] Git: клонировать репозиторий, убедиться что ветки соответствуют окружениям
- [ ] Доступ к панели хостинга (ISPmanager, Plesk, cPanel, или прямой сервер)
- [ ] Доступ к БД (phpMyAdmin или прямой MySQL)
- [ ] Доступ к логам сервера (`/var/log/nginx/`, `/var/log/php/`)

### 1.2 Определить версию и редакцию Bitrix

```bash
cat /var/www/html/bitrix/modules/main/install/version.php
```

В админке: `Настройки → Bitrix Framework → Обновление системы`

- [ ] Записать текущую версию Bitrix (например: 23.1100.0)
- [ ] Записать редакцию (Start / Standard / Small Business / Business / Enterprise)
- [ ] Проверить дату последнего обновления
- [ ] Проверить статус лицензии: `/bitrix/admin/bitrix_license.php`

### 1.3 Инвентаризация установленных модулей

Перейти: `/bitrix/admin/module_admin.php`

- [ ] Экспортировать список установленных модулей
- [ ] Отметить кастомные модули (в `/local/modules/`)
- [ ] Найти устаревшие/неиспользуемые модули

## Фаза 2 — Первые 2 дня: Понимание структуры

### 2.1 Изучить файловую структуру

```bash
# Посмотреть что в local/
ls -la /var/www/html/local/

# Шаблоны сайта
ls /var/www/html/local/templates/
# или
ls /var/www/html/bitrix/templates/

# Кастомные компоненты
find /var/www/html/local/components/ -name "component.php" 2>/dev/null

# Кастомные модули
ls /var/www/html/local/modules/ 2>/dev/null
```

- [ ] Найти шаблон сайта (обычно один основной)
- [ ] Понять структуру `header.php`, `footer.php` в шаблоне
- [ ] Найти `init.php` в `/local/php_interface/init.php`
- [ ] Изучить что подключается в `init.php` (EventHandler'ы, автозагрузка)

### 2.2 Проверить `.gitignore`

Правильный `.gitignore` для Bitrix должен содержать:
```
/bitrix/           ← ядро, обновляется отдельно
/upload/           ← загруженные файлы (большой объём)
*.log
/local/php_interface/dbconn.php   ← пароли БД
*.bak
```

- [ ] Проверить что секреты (пароли, ключи API) не в git
- [ ] Убедиться что `upload/` не трекается

### 2.3 Инфоблоки — основа каталога

Перейти: `/bitrix/admin/iblock_admin.php`

- [ ] Получить список всех инфоблоков
- [ ] Найти инфоблок(и) каталога товаров (тип `catalog`)
- [ ] Найти инфоблок торговых предложений (SKU)
- [ ] Зафиксировать ID инфоблоков (они используются в коде)
- [ ] Изучить свойства основного инфоблока товаров

## Фаза 3 — Дни 2–3: E-commerce конфигурация

### 3.1 Каталог товаров

В Bitrix каталог — это инфоблок + модуль `catalog`. Структура:
- Раздел (CIBlockSection) = категория товаров
- Элемент (CIBlockElement) = товар
- Торговое предложение (SKU) = вариант товара (размер, цвет)

- [ ] Понять структуру разделов (дерево категорий)
- [ ] Найти как устроены SKU: один инфоблок для товаров, отдельный для предложений
- [ ] Проверить группы цен: `/bitrix/admin/cat_price_list.php`
- [ ] Найти склады: `/bitrix/admin/cat_store_list.php`

### 3.2 Заказы и Sale

- [ ] Статусы заказов: `/bitrix/admin/sale_status_admin.php`
- [ ] Платёжные системы: `/bitrix/admin/sale_payment_system_admin.php`
- [ ] Службы доставки: `/bitrix/admin/sale_delivery_service_admin.php`
- [ ] Настройки магазина: `/bitrix/admin/sale_settings.php`
- [ ] Посмотреть несколько реальных заказов: `/bitrix/admin/sale_order_list.php`

### 3.3 Интеграция с 1С (если есть)

- [ ] Проверить наличие CommerceML обмена: `/bitrix/admin/1c_exchange.php`
- [ ] Узнать расписание синхронизации (ручная или автоматическая)
- [ ] Найти логи обмена (`/upload/1c_catalog/`)
- [ ] Уточнить у предыдущей команды: что синхронизируется (товары, заказы, остатки)

## Фаза 4 — Дни 3–4: Среда разработки

### 4.1 Git workflow

Рекомендуемая стратегия веток:
```
main / master       ← production (защищённая ветка)
develop             ← integration (общий dev)
feature/xxx         ← фичи (от develop)
hotfix/xxx          ← срочные исправления (от main)
```

- [ ] Проверить текущий git workflow (есть ли правила?)
- [ ] Договориться о naming convention для веток и коммитов
- [ ] Настроить `.gitignore` если не настроен
- [ ] Убедиться что есть remote для staging (если он есть)

### 4.2 Деплой

Варианты деплоя Bitrix (от простого к сложному):

| Метод | Когда использовать |
|-------|-------------------|
| `git pull` на сервере | Небольшие команды, простой workflow |
| `rsync` скрипт | Когда нужно исключить лишние файлы |
| GitHub Actions / GitLab CI | Автоматизация, staging/prod окружения |
| Deployer (PHP) | Атомарные деплои с rollback |

- [ ] Понять текущую схему деплоя
- [ ] Убедиться что деплой не трогает `upload/` и `dbconn.php`
- [ ] Проверить есть ли возможность откатить изменения

### 4.3 Локальная разработка

- [ ] Поднять локальную копию (Docker / Bitrix VM / XAMPP)
- [ ] Восстановить дамп БД локально
- [ ] Убедиться что сайт работает локально
- [ ] Проверить что лицензия Bitrix работает на dev-домене

## Фаза 6 — Первая неделя: Первые задачи

### Правила разработки на Bitrix

1. **Никогда не редактировать файлы в `/bitrix/`** — они перезапишутся при обновлении
2. **Весь кастомный код — только в `/local/`**
3. **Переопределять компоненты через шаблоны**, не копировать `component.php`
4. **Использовать D7 API** для новых задач (не legacy `CIBlock::`, `CSale::`)
5. **Очищать кеш** после изменений (`/bitrix/admin/cache_del_all.php` или через админку)
6. **Логировать ошибки**: `AddMessage2Log('Сообщение', 'vendor.module')`

### Полезные URL в админке

| URL | Что это |
|-----|---------|
| `/bitrix/admin/` | Главная страница |
| `/bitrix/admin/iblock_admin.php` | Инфоблоки |
| `/bitrix/admin/sale_order_list.php` | Заказы |
| `/bitrix/admin/module_admin.php` | Модули |
| `/bitrix/admin/agent_list.php` | Агенты (фоновые задачи) |
| `/bitrix/admin/event_log.php` | Лог событий |
| `/bitrix/admin/cache_del_all.php` | Очистка кеша |
| `/bitrix/admin/update_system_partner.php` | Обновления Bitrix |
| `/bitrix/admin/security_scanner.php` | Сканер безопасности |
| `/bitrix/admin/phpinfo.php` | Информация о PHP |
